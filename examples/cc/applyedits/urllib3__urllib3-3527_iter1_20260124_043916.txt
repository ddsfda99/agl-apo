Objective
Fix a hang where closing an HTTPResponse from one thread does not interrupt a concurrent blocking read in another thread. The underlying cause is the order and manner in which HTTPResponse.close() cleans up the underlying connection and file-like object. The fix should ensure that closing the response interrupts any active blocking read on the socket, allowing the reading thread to exit promptly, while preserving existing invariants relied upon by urllib3’s tests (especially read_chunked generator semantics).

Important constraints
- Do not commit any changes. Make local edits only; we will commit later.
- Avoid modifying upstream tests unless absolutely necessary. Use a local reproduction harness to validate the fix.
- Ensure determinism in any local concurrency testing (use threading events for synchronization).
- Do not add debug prints to core library code.
- Preserve HTTPResponse invariants used by read_chunked(): do not set self._fp to None in close(); allow the underlying http.client.HTTPResponse to be closed so its internal fp becomes None.

Deliverables
- A robust local reproduction harness that demonstrates the hang and verifies the fix.
- A minimal, surgical code change to urllib3 that resolves the hang without introducing regressions.
- Passing full pytest suite. If time-based tests fail (e.g., RECENT_DATE), update the constant appropriately.
- Cleanup of any temporary files created during reproduction.

Key invariants and behaviors to preserve
- HTTPResponse.supports_chunked_reads() checks hasattr(self._fp, "fp"). This must remain true after close(). Do not set self._fp = None.
- read_chunked() is a generator function. When the response is closed, it should short-circuit such that next(response.read_chunked()) raises StopIteration, not BodyNotHttplibCompatible.
- close() must be idempotent and best-effort. Suppress or safely handle exceptions during close to avoid hanging or masking original errors.
- Do not attempt to drain or consume remaining bytes in close(); draining can cause blocking and reintroduce the hang.

3) Locate the code to change and implement the fix
- Target: src/urllib3/response.py, class HTTPResponse, method close().
- Goal: Proactively interrupt any concurrent blocking read at the OS/socket level by shutting down the socket and then closing the connection before closing the file-like object. Preserve read_chunked semantics by not setting self._fp to None.
- Implementation details:
  - Determine the underlying socket from self._connection if possible:
    - sock = getattr(self._connection, "sock", None)
    - If sock is present, call sock.shutdown(socket.SHUT_RDWR) in a try/except OSError block to ensure any blocked read is interrupted immediately on all platforms.
  - After shutdown, call self._connection.close() if present, in a try/except to suppress errors.
  - Then close the file-like object self._fp best-effort:
    - If self._fp is not None, call self._fp.close() in a try/except to suppress errors.
    - Do not set self._fp = None; allow the underlying http.client.HTTPResponse to set its internal fp to None. This keeps hasattr(self._fp, "fp") true while self._fp.fp becomes None, allowing read_chunked() to short-circuit and next(response.read_chunked()) to raise StopIteration.
  - Ensure idempotency: multiple calls to close() should not raise errors.
  - Do not attempt to drain/consume remaining bytes; avoid any code that reads from the socket during close.
  - Maintain the closed property semantics: after both actions, HTTPResponse.closed should reflect that the response is closed.
  - Add a brief comment explaining the rationale:
    - “Shutdown and close the underlying connection before closing the file-like object to interrupt any concurrent blocking read on another thread. Closing the file-like object first can hang if it attempts to drain remaining bytes. Preserve _fp for read_chunked generator semantics.”
