## Task
**Add first-class support for the `Partitioned` cookie attribute to `Response.set_cookie()`**, aligned with Chrome’s CHIPS / “partitioned cookies” behavior and the direction taken in CPython 3.13.

References:
- Chrome announcement (3PC changes): https://developers.google.com/privacy-sandbox/blog/cookie-countdown-2024jan  
- CHIPS / Partitioned attribute: https://developers.google.com/privacy-sandbox/3pcd/chips  
- CPython issue/PR for Partitioned cookies: https://github.com/python/cpython/issues/112713 and https://github.com/python/cpython/pull/112714

### Functional requirements
1. **`Response.set_cookie()` must accept a new keyword-only argument `partitioned`** (default `False`).
2. When `partitioned=True`, the emitted `Set-Cookie` header must include **`; Partitioned`** as a *flag attribute* (no `=True`).
3. Additionally: **if `same_site` is `'None'` / `None` (i.e., SameSite=None), automatically set `Partitioned`** even if the caller did not pass `partitioned=True`.  
   - Do *not* invent other behavior: specifically **do not force `Secure=True`** automatically. Preserve Falcon’s existing behavior and validations.
4. The implementation must be **native to Falcon**, not a brittle import-time monkey patch in `falcon/__init__.py`.  
   - A minimal compatibility patch to `http.cookies.Morsel` (adding `_reserved['partitioned']` and adding to `_flags`) is acceptable *only if done in an appropriate Falcon module that is reliably imported by the cookie/header generation path*.
5. Ensure the solution works with Falcon’s actual runtime implementation (note: in this repo `falcon.response` may be a compiled extension). Your changes must affect what’s imported at runtime.
