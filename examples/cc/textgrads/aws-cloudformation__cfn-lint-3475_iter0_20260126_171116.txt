Summary of the failure and root cause:
- The underlying bug is that cfn-lint’s GetAtt validation (rule E1010) did not recognize dynamic Outputs on AWS::ServiceCatalog::CloudFormationProvisionedProduct. In the provider schema, this resource has a readOnly property Outputs that allows arbitrary keys via patternProperties, but the GetAtt attribute builder only added a literal “Outputs” attribute, not “Outputs.<key>”. As a result, GetAtt like [ResourceName, Outputs.SomeKey] was flagged invalid.
- A second, closely related issue is rule E1040 (GetAttFormat) comparing the destination format to the attribute’s format. For ProvisionedProduct Outputs, the value type is string and has no “format”. If a destination schema requires a format (e.g., AWS::EC2::VPC.Id), E1040 will fail unless ProvisionedProduct is exempt (similar to nested stacks and custom resources). The current code exempts CustomResource and CloudFormation::Stack, but not ServiceCatalog::CloudFormationProvisionedProduct.

Detailed technical analysis:
- GetAtt attribute generation:
  - In src/cfnlint/schema/_getatts.py, GetAtts builds attributes by walking readOnlyProperties or, for certain types in _all_property_types, recursing into properties. It does not consider patternProperties at all.
  - For AWS::ServiceCatalog::CloudFormationProvisionedProduct, readOnlyProperties includes "/properties/Outputs", which yields an attribute “Outputs”. AttributeDict keys are used for fullmatch against requested attribute names, so “Outputs.Something” won’t match “Outputs”.
  - There is a special-case for AWS::CloudFormation::Stack that adds “Outputs..*” mapped to “/properties/CfnLintStringType” to support nested stack outputs. A similar special-case is needed for ProvisionedProduct.
- Type compatibility (E1010 type check):
  - GetAtt rule simplifies validation to type compatibility (GetAtt.py: lines 105-147). Using the synthetic pointer "/properties/CfnLintStringType" resolves via the resolver to type “string”, which aligns with the schema for ProvisionedProduct Outputs values.
- Format compatibility (E1040):
  - E1040 compares destination “format” (e.g., AWS::EC2::VPC.Id) with the attribute schema’s “format”. Our synthetic pointer returns only type “string” without any “format”, so if the destination expects a format, E1040 will emit a ValidationError unless the resource type is exempt.
  - E1040 currently exempts “AWS::CloudFormation::CustomResource” and “AWS::CloudFormation::Stack” in _resource_type_exceptions. It needs to include “AWS::ServiceCatalog::CloudFormationProvisionedProduct” for parity.
