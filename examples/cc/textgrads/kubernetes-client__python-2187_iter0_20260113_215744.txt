What the bug was
- Symptom: load_kube_config() fails when KUBECONFIG points to multiple colon-separated files where “current-context” is defined in a later file, not the first one. The error raised is “Invalid kube-config file. Expected key current-context in <first file path>”.
- Root cause: KubeConfigMerger was not merging top-level current-context across files. It initialized the merged config from the first file, then cleared clusters/contexts/users but left other keys (including current-context). If the first file did not have current-context, the merged config didn’t either, and KubeConfigLoader.set_active_context accessed _config['current-context'] and raised.

What the agent did
1. Located relevant code quickly:
   - kubernetes/base/config/kube_config.py (KubeConfigMerger and KubeConfigLoader)
   - existing tests in kubernetes/base/config/kube_config_test.py

2. Wrote a focused regression test:
   - Added test_kubeconfig_current_context_from_later_file to create three files (cluster only, context+current-context, user only), set KUBECONFIG with those files in that order, and call load_kube_config(). This reproduced the failure exactly as in the bug description.

3. Identified and fixed the bug:
   - Edited KubeConfigMerger.load_config to merge the top-level “current-context” from each file:
     - After merging clusters/contexts/users, added:
       if 'current-context' in config and config['current-context']:
           self.config_merged.value['current-context'] = config['current-context']
     - This makes later files (non-empty) override earlier ones for current-context. It also ensures that if the first file doesn’t have it, but a later file does, it is set in the merged config.

4. Validated the fix:
   - Ran the test file; it failed before the change, passed after.
   - The change didn’t break existing tests; the entire kube_config_test.py suite passed.

5. Removed the added test case:
   - Consistent with the instruction to clean up and not commit new tests.

Why the original failure happened
- KubeConfigMerger’s initial design copies the first file as a base, clears only clusters/contexts/users, and does not merge top-level keys like current-context across files. KubeConfigLoader requires current-context unless an explicit context is provided. When the first file did not contain current-context, accessing it caused a ConfigException before seeing the later file that defined it.

Summary of the exact fix
- In KubeConfigMerger.load_config (after merging lists), set current-context if present and non-empty in the current file:
  - if 'current-context' in config and config['current-context']:
        self.config_merged.value['current-context'] = config['current-context']
- This ensures that when the KUBECONFIG value includes files in any order, current-context can come from any later file, matching kubectl’s merging behavior.
