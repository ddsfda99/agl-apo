The agent fixed the *symptom* (symbolic call raising) by removing the `query_shape[-1] != value_shape[-1]` check in `MultiHeadAttention.compute_output_shape()`, but it did **not** ensure the repository test suite still passes. Running the project’s own tests immediately exposed a regression:

This happened because that test passes `key_shape=2` (an `int`, intentionally) and previously the method would raise earlier (on query/value last-dim mismatch) before touching `key_shape`. After removing the first guard, the code now reaches slicing `key_shape` and crashes.

So the agent’s change **broke an existing test contract**: even if we think the query/value check was wrong, removing it requires either:
1) updating the tests to the new intended behavior, **and/or**
2) making `compute_output_shape()` robust to invalid `key_shape` argument types (raise a clean `ValueError` instead of crashing).

The agent did neither, and then stopped with a narrative response rather than completing the fix.

### Additional subtlety the agent missed

`compute_output_spec()` currently constructs attention score shape as `(batch, num_heads, length, length)` where `length = query.shape[1]`. That assumes S==T for scores, which isn’t always true for cross-attention (query length != value/key length). This isn’t what failed here, but if you’re touching shape logic, it’s worth sanity-checking.
