Summary of the reported bug
- On Fedora (RHEL-based), when rpm-build is missing, Briefcase prompts the user to install “rpmbuild” via “sudo dnf install rpmbuild”. This is incorrect; the package is named “rpm-build”.
- Expected prompt: “sudo dnf install rpm-build”.

Where the bug is in the code
- The mapping that drives the install prompt is in src/briefcase/platforms/linux/system.py, in LinuxSystemPackageCommand._verify_packaging_tools():
  tool_name, executable_name, package_name = {
      "deb": ("dpkg", "dpkg-deb", "dpkg-dev"),
      "rpm": ("rpm-build", "rpmbuild", "rpmbuild"),
      "pkg": ("makepkg", "makepkg", "pacman"),
  }[app.packaging_format]

- For RPM, the third item in the tuple is the package name to install. That currently is "rpmbuild", which is incorrect on Fedora. It should be "rpm-build".
- The install command uses that package_name along with the installer returned by _system_requirement_tools(app) for RHEL-based systems: ["dnf", "install"].
- Therefore, the fix required in code is to change the mapping for "rpm" to ("rpm-build", "rpmbuild", "rpm-build").
