Summary of the reported bug
- Error: "Error executing tool search: SearchMixin.search_issues() got an unexpected keyword argument 'start_at'"
- Occurs when calling the jira_search tool/command to paginate search results.
- Environment: Jira Server/DC, Python 3.11.2, mcp-atlassian 1.6.0, Docker.

Root cause analysis
- The error message points to a mismatch in keyword arguments. Specifically, the SearchMixin.search_issues signature uses a parameter named "start", not "start_at", while the FastMCP server tool layer calls it with "start_at".
- This mismatch leads to Python raising: unexpected keyword argument 'start_at'.

Code evidence
- SearchMixin.search_issues in src/mcp_atlassian/jira/search.py:
  - Signature: def search_issues(self, jql, ..., start: int = 0, limit: int = 50, ...)
  - It calls self.jira.jql(..., start=start, limit=limit, ...).
- Servers tool search in src/mcp_atlassian/servers/jira.py:
  - The tool async def search(... start_at: int = 0 ...) calls fetcher.search_issues(... start_at=start_at ...).
  - That is a direct mismatch (start_at vs start) that triggers the error.

- Similar mismatches exist in other server tools:
  - get_project_issues tool calls fetcher.get_project_issues with start_at keyword, but ProjectsMixin.get_project_issues signature is def get_project_issues(self, project_key, start: int = 0, limit: int = 50).
  - get_agile_boards tool calls fetcher.get_boards(... start_at=start_at ...). The Boards mixin defines get_all_agile_boards(... start: int = 0, limit: int = 50). If JiraFetcher does not alias get_boards to accept start_at, this will also fail.
  - get_sprints_from_board tool calls fetcher.get_sprints(... start_at=start_at ...). The Sprints mixin defines get_all_sprints_from_board(... start: int = 0, limit: int = 50).
  - get_board_issues and get_sprint_issues tools pass start_at to the fetcher methods. The corresponding mixin methods use start.
