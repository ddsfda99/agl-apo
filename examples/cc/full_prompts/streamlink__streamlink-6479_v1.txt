Goal
Fix a regression in streamlink’s HLS audio selection where --hls-audio-select no longer matches HLS audio tracks by their NAME attribute. Restore the previous behavior so that items in --hls-audio-select can match:
- Language codes (e.g., en, fr, de, es)
- Recognized language names (localized variants handled by utils.l10n)
- HLS #EXT-X-MEDIA NAME values (case-insensitive exact match, trimmed)

Scope and constraints
- Implement a minimal, targeted fix that restores previously working behavior without broadening semantics beyond NAME matching.
- Add only the tests necessary to reproduce and validate the bug fix as per the steps below.
- Do not modify unrelated tests or broaden the feature set.
- Do not commit your edits. We will do it later.

Background and observed behavior
User reports that after updating to streamlink 7.1.3+28.g14761c91, using --hls-audio-select "TV Ton,Originalton" or "--hls-audio-select 'Deutsch,Original'" no longer selects multiple audio tracks by their NAME labels as it did before. Language code selection still works (e.g., "en,fr,it,es"), but name-based selection (e.g., "English,Français,Deutsch,Español") does not.

Acceptance criteria
- When audio-select includes non-language tokens matching the HLS #EXT-X-MEDIA NAME attribute (case-insensitive, trimmed), those audio tracks must be selected.
- Multiple audio tracks can be selected by NAME and by language (union of matches), maintaining the selection order given by the user tokens.
- Language code selection continues working exactly as before, unchanged.
- Selection is limited to the audio tracks belonging to the selected video variant’s GROUP-ID.
- No duplicate audio tracks are added to the external audio list (deduplicate by URI).
- Tests reproducing the bug should fail before the fix and pass after the fix.

4) Implement the fix
- Extend the audio selection logic to include a match against the HLS #EXT-X-MEDIA NAME attribute when a user token is not recognized as a language code or mapped language name:

  - Only consider NAME matches for media.type == AUDIO and media.group_id matching the selected variant’s AUDIO group-id.
  - Preserve the existing behavior and precedence for language code/name matches. Do not change how language code/name resolution currently works.
- Ensure:
  - Multiple selections are supported; order of selection should follow the order of user tokens.
  - Deduplicate external audio tracks by URI if multiple tokens match the same media entry.
  - No change in behavior for language-code-driven selection.

Implementation notes and hints

- Consider using casefold or lower() for case-insensitive matching; trimming whitespace is necessary. Unicode normalization is optional; direct matching of “Français” should work without extra normalization.
