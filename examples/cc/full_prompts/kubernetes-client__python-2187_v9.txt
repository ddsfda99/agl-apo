Background and root cause
- Symptom: When KUBECONFIG contains multiple files and only a later file defines current-context, load_kube_config raises “Invalid kube-config file. Expected key current-context in <first-file-path>”.
- Expected: Mimic kubectl. Merge all files first; for conflicts the last file wins. The merged config’s current-context should come from the last file that defines it. Order should not matter.
- Root cause: In KubeConfigMerger.load_config, only list fields (clusters, contexts, users) are merged. Scalar top-level keys such as current-context are not updated based on later files. KubeConfigLoader.__init__ calls set_active_context(), which immediately reads current-context from the merged config. If the first file does not have current-context, it raises with the first file’s path.
