Add **first-class support for the `Partitioned` cookie attribute** to `Response.set_cookie()`, aligned with Chrome’s CHIPS / “partitioned cookies” behavior and CPython 3.13 direction.

## Functional requirements (must all be met)

1. `Response.set_cookie()` must accept a new **keyword-only** argument:  
   - `partitioned: bool = False`

2. When `partitioned=True`, the emitted `Set-Cookie` header must include the **flag attribute**:
   - `; Partitioned`  
   and **must not** emit `Partitioned=True` or `Partitioned=1`.

3. Auto behavior (CHIPS expectation):
   - If `same_site` is `'None'` (case-insensitive) **or** `None` (treat as “SameSite=None” for purposes of this feature), then **automatically set Partitioned**, even if the caller did not pass `partitioned=True`.
   - Do **not** invent any other behavior: specifically **do not auto-force `Secure=True`**. Preserve Falcon’s existing validations and behavior.

4. Implementation must be **native to Falcon**, not a brittle import-time monkey patch of `falcon.Response.set_cookie` in `falcon/__init__.py`.

5. Minimal compatibility patch to `http.cookies.Morsel` is allowed **only** in a stable Falcon module that is reliably imported by the cookie/header generation path:
   - Add `_reserved['partitioned'] = 'Partitioned'`
   - Add `'partitioned'` to `_flags`
   - **Do not** override `Morsel.__setitem__` or other methods.
