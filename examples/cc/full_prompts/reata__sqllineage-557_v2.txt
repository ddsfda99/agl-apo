Bug description: set target table column name from MetaDataProvider
**Is your feature request related to a problem? Please describe.**
sql: "insert into target select user_id, user_name from source"
target's column is id, name
column lineage 's target column is user_id, user_name from sql parse

**Describe the solution you'd like**
use MetaDataProvider, search target table's column ,write to Holder.
equal  "insert into target(id, name) select user_id, user_name from source"





Objective
- Fix column lineage for INSERT INTO target SELECT ... FROM source statements without an explicit target column list so that, when a MetaDataProvider is available and the selected column count matches the target table’s column count, lineage uses the actual target table’s column names.

Context and desired behavior
- Current behavior: For INSERT … SELECT without target columns specified, lineage uses the names from the SELECT list (e.g., user_id, user_name) as the target column names.
- Desired behavior: If a MetaDataProvider can supply the target table’s column list and the count matches the number of selected columns, treat it as if the SQL had explicitly specified the target column list. For example, turn lineage from user_id -> user_id, user_name -> user_name into user_id -> id, user_name -> name for the target table.

Where to change the code
- File: sqllineage/core/parser/__init__.py
- Class: SourceHandlerMixin
- Method: end_of_query_cleanup
- Root cause: Target columns are only set when explicitly provided in the INSERT. When not provided, holder.write_columns is empty, so lineage falls back to using the SELECT list’s column names. There is no logic to populate holder.write_columns from the MetaDataProvider for this case.
- Fix approach: Populate holder.write_columns from the MetaDataProvider when it is empty and counts match, before the existing logic that checks len(holder.write_columns) == len(col_grp).

Implementation details in end_of_query_cleanup
- Within the loop that processes each union segment (the method already identifies union barriers and the selected column group, commonly referenced as col_grp), determine the single target table (tgt_tbl) from holder.write.
- If holder.write_columns is empty and a metadata provider exists on self, fetch the target table’s column names from the metadata provider.
- Only populate write_columns if:
  - tgt_tbl is a Table object (not a SubQuery)
  - The provider returns a non-empty list of columns
  - The number of returned target columns equals len(col_grp)
- Call holder.add_write_column(*target_columns) to set them. Do not override if write_columns is already populated.
- Ensure this logic runs before the existing logic that checks len(holder.write_columns) == len(col_grp).

- After computing tgt_tbl for the current statement and before using write_columns to resolve target column names:

      - target_columns = metadata_provider.get_table_columns(tgt_tbl)
      - if target_columns and len(target_columns) == len(col_grp):
        - holder.add_write_column(*target_columns)
