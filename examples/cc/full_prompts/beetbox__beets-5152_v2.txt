You are an expert in coding agent prompt optimization. Your task is to produce a robust, verifiable fix for the fetchart plugin bug where only one of multiple needed image operations is executed, causing PNG images over max_filesize with cover_format=JPEG to fail to be processed correctly.

Context and observed bug
- Environment: Windows, Python 3.11.0b1, beets at commit b09806e0df8f01b9155017d3693764ae7beedcd5
- Config example:
  plugins: fetchart
  fetchart:
    sources:
      - filesystem
      - coverart: release
      - itunes
      - amazon
      - albumart
      - coverart: releasegroup
      - "*"
    max_filesize: 3500000
    cover_format: JPEG
- Problem: A PNG cover larger than max_filesize should be both reformatted to JPEG and then downsized to fit the size budget. Currently, beetsplug/fetchart.py Candidate._validate returns only a single operation (first match) with early returns in priority order (downscale -> downsize -> deinterlace -> reformat -> exact). Candidate.resize then applies only that single operation, so when a PNG needs both reformatting and downsizing, only downsizing is attempted. PIL’s filesize reduction via quality works for JPEG but not PNG, so the downsizing attempt is ineffective and reformat never occurs.

Goal
- Ensure a candidate image can undergo multiple required operations in the correct order, specifically:
  1) Reformat (e.g., PNG -> JPEG) when cover_format requires it.
  2) Deinterlace if requested and not already handled by reformat.
  3) Resize (downscale by dimensions and/or downsize by target filesize).
- Add a reproduction test that verifies the correct sequence (reformat before resize) is performed when both are necessary.
- Use the built-in unittest framework (not pytest), and use mocks to avoid reliance on external dependencies when possible.
- Do not commit your edits.

4) Implement the fix

Implementation guidance and notes
- Be cautious about call order and side effects:
  - Reformat must happen before any filesize-based resize when the source is PNG and target is JPEG.
  - If reformatting already applies deinterlace via its parameter, do not perform deinterlace again.
- ArtResizer API:
  - ArtResizer.shared.reformat should accept parameters to set the target format and possibly deinterlace.
  - ArtResizer.shared.resize should accept parameters for maxwidth and/or max_filesize.
  - Do not rely on PNG quality settings for filesize reduction; PIL’s quality param is for JPEG.
- When mocking in tests, patch symbols in the beetsplug.fetchart import context (e.g., beetsplug.fetchart.ArtResizer.shared.reformat), not the class definition elsewhere, to ensure the code under test uses the mocks.
- Assert call order using mock_calls or separate MagicMocks and compare their call indices.
- Document in code comments the rationale for the operation order so future refactors don’t reintroduce the bug.
