Context on the bug
- Symptom: load_kube_config fails when KUBECONFIG contains multiple files and only a later file defines current-context. The error is “Invalid kube-config file. Expected key current-context in <first-file-path>”.
- Expected: Match kubectl behavior. Merge all files first, then read current-context from the merged config. Order should not matter. For conflicts, the last file wins.
- Root cause: In KubeConfigMerger.load_config, the merger deep copies the first file and merges only the lists clusters, contexts, and users. Scalar top-level keys (like current-context) are not updated based on later files. KubeConfigLoader.__init__ calls set_active_context(), which immediately accesses current-context on the merged config and raises if missing.
