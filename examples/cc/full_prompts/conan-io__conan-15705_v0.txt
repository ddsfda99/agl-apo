You are given a code repository in the current directory.
The task description is:
[feature] Allow self.name in tools.cmake.cmake_layout:build_folder_vars
In our org we have multiple recipes with a shared code basis. The directory structure is as following:
```sh
.
├── CMakeLists.txt
├── simple_example.cc
├── sub1
│   └── conanfile.py
└── sub2
    └── conanfile.py
```
The conan files look something like this:
```python
from conan import ConanFile
from conan.tools.cmake import CMakeToolchain, CMake, cmake_layout

class sub2Recipe(ConanFile):
    name = "sub2"
    version = "1.0"
    def layout(self):
        cmake_layout(self, generator="Ninja", src_folder="..")

    def generate(self):
        tc = CMakeToolchain(self)
        tc.generate()

    def build(self):
        cmake = CMake(self)
        cmake.configure()
        cmake.build()
```
When I now run:
```sh
 conan install sub1/conanfile.py
 conan install sub2/conanfile.py
``` 

I get a CMakeUserPresets.json that refers to both CMakePresets.json in their respective `subX/build/generators/CMakePresets.json` folder. The problem now is that for both CMakePresets the names are identical:
```json
    "configurePresets": [
        {
            "name": "release",
            "displayName": "'release' config",
            "description": "'release' configure using 'Unix Makefiles' generator",
            ...
        }
    ],
    "buildPresets": [
        {
            "name": "release",
            "configurePreset": "release"
        }
    ],
```

VSCode will show both displayNames and it is impossible to tell which one is going to build what.

So my idea of how to fix that would be the following, allow to run install like this:
```sh
conan install -ctools.cmake.cmake_layout:build_folder_vars="['self.name']" sub1/conanfile.py
```

Which results in:
```json
    "configurePresets": [
        {
            "name": "sub1-release",
            "displayName": "'sub1-release' config",
            "description": "'sub1-release' configure using 'Unix Makefiles' generator",
            ...
        }
    ],
    "buildPresets": [
        {
            "name": "sub1-release",
            "configurePreset": "sub1-release"
        }
    ],
```

Another nice side-effect is that I can also have a common build folder at the "root":
```
cmake_layout(self, generator="Ninja", src_folder="..", build_folder="../build")
```
