Bug description: Warn users when adding the same component instance to multiple pipelines
Adding the same component instance to different pipelines causes side effects that often result in unexpected behaviour.

Except for any operation done during the `warm_up` phase, components are stateless so there's no gain in adding the same instance to different pipelines, and our stance at this point in time is we don't support it.

We need to document this and add a meaningful error in `add_component` to detect if an instance is already part of another pipeline, and in case failing the operation explaining why.


Goal
Prevent adding the same component instance to multiple pipelines. Add a meaningful error in Pipeline.add_component when the instance is already part of a different Pipeline, and explain why this is unsupported.

What to implement
- Track ownership of a component instance when it is first added to a Pipeline.
- If the same instance is added to a different Pipeline, raise a clear, actionable error (PipelineValidationError) explaining that reusing instances across pipelines can cause side effects and is unsupported. Suggest creating a new instance for each pipeline.
- Ensure this check applies to all ways of constructing pipelines that eventually call add_component (including from_dict).
- Update any misleading docstrings/comments that currently say instances can be reused across pipelines, including the from_dict docstring.

Process guardrails
- Run only the new targeted tests you add for this bug. Do not run the entire test suite; unrelated integration tests may fail due to external dependencies and will add noise.
- Keep the fix minimal and localized to add_component and docstrings. Do not change public APIs beyond raising the new error.
- After validating the fix, delete the temporary test files you added and do not commit any changes.
