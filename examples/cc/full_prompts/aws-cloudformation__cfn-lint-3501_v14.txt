## Issue to fix
**W2001 “Parameter not used” false positive when using `Fn::Transform` (`AWS::Include`) in `AWS::ApiGateway::RestApi` `Body`**  
*cfn-lint version: 0.55.0*

### Scenario
A CloudFormation template (`api.cfn`) includes an OpenAPI/Swagger file (`api-specification.yml`) using:

```yaml
Body:
  Fn::Transform:
    Name: AWS::Include
    Parameters:
      Location: ./api-specification.yml
```

The included file contains intrinsic functions like `Fn::Sub` referencing template parameters (e.g., `${PetLambdaArn}`, `${UserPoolArn}`). cfn-lint currently warns W2001 that these parameters are unused because it only scans the main template, not the included file.

### Required behavior
Parameters referenced in the included file must be treated as **used** for purposes of W2001.  
Do **not** “fix” this by disabling W2001 whenever `Fn::Transform` or `AWS::Include` appears. That broad suppression is incorrect and will hide real unused-parameter warnings.

3. **Be careful about `Fn::Transform` representation:** YAML may parse transforms differently; don’t assume only one exact dict shape without checking how this repo parses templates.

## What to implement (high-level guidance)
Implement support so that when the template contains an `Fn::Transform` with `Name: AWS::Include`, the linter:
1. Resolves the `Location` file path (at least local relative paths).
2. Loads and parses the included file (YAML/JSON).
3. Finds intrinsic usage patterns in the included structure, at minimum:
   - `Ref: SomeParam`
   - `Fn::Sub` strings containing `${SomeParam}` (and `Fn::Sub` list form, if present)
4. Feeds those discovered parameter names into the same “used parameter” detection that W2001 relies on.

### Where to hook this
Prefer a solution that integrates into existing template preprocessing/transform tracking (e.g., whatever builds `cfn.transform_pre[...]`) so other rules can reuse it.  
If that’s too invasive, a minimal acceptable approach is enhancing the W2001 implementation to additionally scan included files and merge results into its used-set—**but do not return early or disable the rule**.
