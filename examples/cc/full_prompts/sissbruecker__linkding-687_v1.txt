Context and root cause
- The error ENAMETOOLONG occurs because the snapshot filename includes the entire sanitized URL without a cap. This is built in bookmarks/services/tasks.py in the helper _generate_snapshot_filename.
- The generated filename looks like: snapshot_YYYY-MM-DD_HHMMSS_<sanitized_url>.html.gz
- singlefile.create_snapshot writes a temporary file by appending “.tmp” to this name. On many filesystems the max filename length is 255 bytes. If you cap the base filename at 255 but don’t account for “.tmp”, the temporary filename can still exceed the limit.
- The correct fix is to cap the base filename length at 255 - len(".tmp") = 251 characters, and for long URLs, append a short, deterministic hash to avoid collisions.

  import hashlib

  def _generate_snapshot_filename(asset):
      formatted_datetime = asset.date_created.strftime("%Y-%m-%d_%H%M%S")
      sanitized_url = "".join(
          ch if ch.isalnum() or ch in "-_." else "_" for ch in asset.bookmark.url
      )
      prefix = f"{asset.asset_type}_{formatted_datetime}_"
      ext = ".html.gz"
      tmp_suffix = ".tmp"
      max_filename_len = 255 - len(tmp_suffix)

      # Defensive guard in the unlikely event prefix + ext already exceeds the cap
      if len(prefix) + len(ext) >= max_filename_len:
          hash8 = hashlib.sha1(asset.bookmark.url.encode("utf-8")).hexdigest()[:8]
          available = max(0, max_filename_len - len(prefix) - 1 - len(hash8) - len(ext))
          truncated = sanitized_url[:available]
          return f"{prefix}{truncated}_{hash8}{ext}"

      max_url_len = max_filename_len - len(prefix) - len(ext)

      if len(sanitized_url) <= max_url_len:
          return f"{prefix}{sanitized_url}{ext}"

      hash8 = hashlib.sha1(asset.bookmark.url.encode("utf-8")).hexdigest()[:8]
      # Reserve room for "_" + hash8
      truncated = sanitized_url[: max_url_len - 1 - len(hash8)]
      return f"{prefix}{truncated}_{hash8}{ext}"
