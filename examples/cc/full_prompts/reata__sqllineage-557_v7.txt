You are working in the repository at /testbed. Your goal is to implement a feature fix: when an INSERT INTO ... SELECT ... statement does not specify a target column list, infer the target column names from MetaDataProvider and use them as the target-side columns in column lineage, provided the number of inferred target columns matches the number of columns in the SELECT list. This should make the lineage behave as if the SQL had explicitly specified the target columns.

Background and current problem
- Scenario: SQL is "insert into target select user_id, user_name from source". The physical target table columns are id, name.
- Current behavior: Column lineage uses user_id, user_name as target-side column names (from the SELECT list), which is incorrect.
- Desired behavior: If the target column list is not specified, fetch the target table’s columns from MetaDataProvider and use those names as target-side columns. Effectively treat it like "insert into target(id, name) select user_id, user_name from source".

Where to change
- The main logic that wires column lineage for the sqlfluff analyzer path is in SourceHandlerMixin.end_of_query_cleanup in sqllineage/core/parser/__init__.py.
- Existing behavior:
  - It iterates over the selected columns (col_grp).
  - Sets the parent of each target column to the target table.
  - By default, sets tgt_col_resolved = tgt_col_from_query.
  - If len(holder.write_columns) == len(col_grp), it substitutes tgt_col_resolved = holder.write_columns[idx] (write_columns are populated when the INSERT statement explicitly lists target columns or via DDL).
  - Then it resolves source columns and adds lineage edges.

Root cause
- There is no logic to derive target columns from the target table schema via MetaDataProvider when target columns are not specified in the SQL. Therefore, the code incorrectly uses SELECT list column names on the target side.

What you need to implement
- In SourceHandlerMixin.end_of_query_cleanup, extend the mapping of target-side columns:
  - Keep existing behavior that if len(holder.write_columns) == len(col_grp), use holder.write_columns[idx].
  - Otherwise, if a metadata provider is available and the write target is a concrete Table, fetch the target table’s columns using the metadata provider. If the number of columns equals len(col_grp), use those target table columns indexed correspondingly to substitute tgt_col_resolved.
  - Only perform this mapping when the lengths match; otherwise, leave the current behavior unchanged.
  - Ensure you set the parent for the resolved target columns to the target table if not already set consistently.
- Access the metadata provider safely: metadata_provider = getattr(self, "metadata_provider", None).
- Only attempt metadata lookup if the write target is a Table (not a SubQuery, CTE, etc.).
- This mirrors the behavior of explicit "INSERT INTO target(col1, col2) SELECT ..." but uses metadata when the column list is omitted.
