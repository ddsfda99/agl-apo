# Prompt Template

You are given a code repository in the current directory (/testbed).
    The bug description is:
    {description}
    =================================================
    You task is to fix the bug with the following steps:
    (1) write test cases to reproduce the bug.
    (2) explore the source codes to locate the bug.
    (3) edit the source codes to fix the bug.
    (4) rerun your written test cases to validate that the bug is fixed. If not, go back to explore the source codes and fix the codes again.
    (5) remember to delete the test cases you write at last.
    Please do not commit your edits. We will do it later.

# Critique

# Prompt Critique

## 1. Structural Issues

- **Goal Stated**: The prompt clearly states the goal is to fix a given bug in a code repository, following a specified list of steps.
- **Stop Condition**: It provides a concrete finish ("remember to delete the test cases you write at last") and says "do not commit your edits," which is clear.
- **No Contradictions or Cycles**: Steps are sequential; nothing blocks logical progress.

**Status**: Clear.

## 2. Instruction Quality

- **Specificity**: Instructions are concrete ("write test cases," "explore source codes," etc.).
- **Abstraction**: All instructions are implementation-level; no high-level or principle-based instructions are interleaved.
- **Hierarchy**: All instructions are listed with equal weight, but no conflicts exist, so explicit hierarchy/rule priority is not needed.
- **No Redundant Steps**: Each step is unique and non-overlapping.

**Status**: Clear and direct.

## 3. Control and Behavior

- **Tool Use**: The prompt does not specify allowed/disallowed tools (e.g., whether to use certain linters or test runners, or time/tokens for actions).
- **Uncertainty Handling**: No guidance for when inputs are missing/ambiguous or if the bug is unreproducible.
- **Verbosity**: No explicit instruction on the level of explanation/detail for intermediary outputs (e.g., whether to output just code or also discussion).
- **Feedback**: No requirements for progress reporting or check-ins for multi-step processes.

**Status**: Incomplete. Could be improved by clarifying tool limits and output verbosity.

## 4. Input and Output Specification

- **Input Defaults**: No specification for missing/invalid "bug description."
- **Output Schema**: There is no specification on the output format (code, plain text, Markdown), or file naming expectations.
- **Validation**: No step to confirm that the fix is correct beyond passing the tests.

**Status**: Incomplete.

## 5. Scope and Safety

- **Scope**: The scope is well-bounded (test, code, validate, clean up), with a safety net ("do not commit your edits").
- **Irreversible Actions**: "Delete the test cases you write at last" could, in some contexts, risk removing user tests if not careful.
- **No Error Handling**: No instructions if a test fails due to reasons unrelated to the bug.

**Status**: Clear but could add error handling for 'delete'.

## 6. Efficiency and Maintainability

- **Conciseness**: The steps are efficiently stated and easy to audit.
- **No Redundancy**: No duplicate guidance.
- **No Hidden Defaults**: Assumes Pythonic workflow but doesn't state language, time zone, or environment explicitly.
- **Auditability**: Step structure is clear, but a section heading (e.g., "# Procedure") would help auditing.

**Status**: Mostly clear; minor auditability improvements possible.

## 7. Testing Method Check

The intended outcome and sequence are clear. The prompt would pass a clarity test but could benefit from defined expected output and more error handling.

---

**Summary**:

**Structure**: Clear and sequential.
**Instruction Quality**: Precise, but could clarify output format and verbosity.
**Control**: Lacks tool/timeout limits and guidance on ambiguity.
**Input/Output**: No schema or missing input safety nets; no output format specified.
**Scope/Safety**: Mostly safe, but deletion step could be hazardous in non-isolated environments.
**Efficiency**: Efficient instructions, but minor structure improvements would help audit.
**Rating**: Clear in structure and goals, but incomplete in specifying output schema, error handling, and tool boundaries.
