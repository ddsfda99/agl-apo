### PROMPT

You are given a code repository in the current directory (/testbed).
    The bug description is:
    {description}
    =================================================
    You task is to fix the bug with the following steps:
    (1) write test cases to reproduce the bug.
    (2) explore the source codes to locate the bug.
    (3) edit the source codes to fix the bug.
    (4) rerun your written test cases to validate that the bug is fixed. If not, go back to explore the source codes and fix the codes again.
    (5) remember to delete the test cases you write at last.
    Please do not commit your edits. We will do it later.

- The prompt defines a clear goal: fix a described bug by following specified steps (writing tests, exploring code, editing, validating via tests, deleting temporary tests).
- It specifies a stop condition: finish after tests validate the fix and temporary tests are deleted.
- No contradictions or circular dependencies are evident.

- Instructions are sequential and numbered, clarifying steps.

- The prompt mixes high-level guidance (fix the bug) with implementation steps but remains mostly coherent.

- Output verbosity is unspecified.
- No feedback or progress reporting requested.

Input and Output Specification:

Efficiency and Maintainability:

Summary:
The prompt is structurally sound with a clear, actionable goal and stepwise instructions, enabling focused bug fixing. However, it lacks explicit guidance on output formatting, tool usage limits, uncertainty handling, and error reporting. Verbs like “explore” and “edit” are somewhat vague, potentially leading to inconsistent behavior. The prompt would benefit from explicit output schema, instructions for error handling, and possible clarifying questions. Overall, it is clear and concise but could be enhanced for robustness and precision.
