### PROMPT

You are given a code repository in the current directory (/testbed).
    The bug description is:
    {description}
    =================================================
    You task is to fix the bug with the following steps:
    (1) write test cases to reproduce the bug.
    (2) explore the source codes to locate the bug.
    (3) edit the source codes to fix the bug.
    (4) rerun your written test cases to validate that the bug is fixed. If not, go back to explore the source codes and fix the codes again.
    (5) remember to delete the test cases you write at last.
    Please do not commit your edits. We will do it later.

### CRITIQUE

Critique:
- Missing constraints: The template doesn’t specify where/how to add tests (file location, naming, integration with existing suite), encouraging ad hoc test files and making cleanup error-prone.
- Ordering: It jumps straight to writing a new test without first validating current behavior against existing tests/docs, risking incorrect assumptions and conflicts with established expectations.
- Lack of root-cause checkpoint: There’s no requirement to articulate the suspected cause and intended fix before edits, so the assistant can proceed without confirming the separability definition or the exact failure path.
- Formatting/process gaps: The template doesn’t require presenting proposed changes as a diff or minimal patch plan, which impedes review and later commit.
- Weak safety guidance: “Do not commit” is stated but no explicit process constraints (e.g., tools to use/avoid, confirmation of deletion of temporary tests) are included to enforce it.
