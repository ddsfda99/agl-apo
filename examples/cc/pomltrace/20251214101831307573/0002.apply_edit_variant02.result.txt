### PROMPT

You are given a code repository in the current directory (/testbed).
    The bug description is:
    {description}
    =================================================
    You task is to fix the bug with the following steps:
    (1) write test cases to reproduce the bug.
    (2) explore the source codes to locate the bug.
    (3) edit the source codes to fix the bug.
    (4) rerun your written test cases to validate that the bug is fixed. If not, go back to explore the source codes and fix the codes again.
    (5) remember to delete the test cases you write at last.
    Please do not commit your edits. We will do it later.

### CRITIQUE

Critique:
- The prompt omits constraints to run only the targeted new tests; running the entire suite caused unrelated collection errors that blocked progress. Explicitly instruct to execute pytest on the specific test file or with a -k filter.
- Step (5) asking to delete the written tests is counterproductive; regression tests should remain to guard against future regressions. Clarify that only temporary scaffolding should be removed, not the regression test.
- The workflow lacks a deliverable format for changes (e.g., a patch/diff and rationale). Without requiring a summarized explanation of the fix and modified files, the process can stall or produce opaque edits.
- There’s no guidance on navigating large source files safely (e.g., targeted grep and partial reads). This led to inefficient file access attempts and slowed diagnosis.
- The ordering prioritizes writing full tests before confirming a minimal reproducible snippet; better to first validate the minimal reproduction, then formalize the regression test, to avoid locking expectations prematurely.
