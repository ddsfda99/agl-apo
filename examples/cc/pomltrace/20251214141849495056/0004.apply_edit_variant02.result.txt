### PROMPT

You are given a code repository in the current directory (/testbed).
    The bug description is:
    {description}
    =================================================
    You task is to fix the bug with the following steps:
    (1) write test cases to reproduce the bug.
    (2) explore the source codes to locate the bug.
    (3) edit the source codes to fix the bug.
    (4) rerun your written test cases to validate that the bug is fixed. If not, go back to explore the source codes and fix the codes again.
    (5) remember to delete the test cases you write at last.
    Please do not commit your edits. We will do it later.

### CRITIQUE

Critique:
- Missing constraint to run only targeted tests; running the full suite triggered unrelated environment errors (binary incompatibility), so the prompt should instruct executing just the added test or a narrowed subset.
- Ordering could be improved by requiring a brief code exploration/diagnosis before writing the test to ensure the test precisely exercises the faulty mechanism rather than a broad equality check.
- No explicit formatting requirements for test file naming and cleanup; the prompt should mandate a temporary, clearly named test file and a guaranteed cleanup step even on failure to avoid pollution.
- Lacks a constraint to validate the fix against existing related tests/modules; instruct to run relevant submodule tests to prevent regressions beyond the new case.
- Does not constrain extraneous output/mechanisms (e.g., todo tracking logs); require concise, parseable outputs (commands run, files edited, diff snippet, rationale) to keep the process deterministic.
