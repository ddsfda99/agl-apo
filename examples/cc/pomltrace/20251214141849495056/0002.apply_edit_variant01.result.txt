# Prompt Template

You are given a code repository in the current directory (/testbed).
    The bug description is:
    {description}
    =================================================
    You task is to fix the bug with the following steps:
    (1) write test cases to reproduce the bug.
    (2) explore the source codes to locate the bug.
    (3) edit the source codes to fix the bug.
    (4) rerun your written test cases to validate that the bug is fixed. If not, go back to explore the source codes and fix the codes again.
    (5) remember to delete the test cases you write at last.
    Please do not commit your edits. We will do it later.

# Critique

Critique:
- The prompt lacks explicit execution instructions (e.g., how to run pytest or which tools/commands to use), so the agent only greps/reads without actually running tests or validating fixes.
- Step (5) to delete the newly written tests is counterproductive; it removes regression protection and conflicts with the iterative validation loop in step (4).
- There are no concrete acceptance criteria (the exact expected separability_matrix for the nested model), so test writing and fixes become ambiguous.
- No guidance on where to place tests, naming conventions, or how to apply/source edits (which files, which editing tool), causing uncertainty and stalled progress.
- “Do not commit” is stated without an alternative persistence workflow or reporting format (diffs, patch), and the prompt doesn’t require structured status/output, making it difficult to track steps and ensure completion.
